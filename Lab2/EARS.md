# EARS

| ID | Вимога |
|---|---|
| REQ-01 | **WHILE** режим "Строге дотримання фільтру" вимкнено, **WHEN** користувач підтвердив вибір Taste, система **SHALL** показати рецепти, які мають хоча б один з обраних Taste. |
| REQ-02 | **WHILE** режим "Строге дотримання фільтру" увімкнено, **WHEN** користувач підтвердив вибір Taste, система **SHALL** показати рецепти, які мають усі обрані Taste. |
| REQ-03 | **WHEN** користувач підтвердив вибір Taste, **IF** жоден Recipe не має обраного набору Taste (з урахуванням режиму), **THEN** система **SHALL** показати повідомлення "Рецептів за обраними смаками не знайдено". |
| REQ-04 | Система **SHALL** ігнорувати Intensity під час відбору рецептів за Taste. |
| REQ-05 | **WHEN** користувач підтвердив вибір Ingredient для підбору, система **SHALL** показати Recipe, у яких усі Category з RecipeItemQuantity входять до множини Category обраних Ingredient. |
| REQ-06 | **WHEN** користувач оформив замовлення, система **SHALL** зберегти в кожній ItemQuantity значення PriceAtOrder, скопіювавши його з Ingredient.Price на момент оформлення. |
| REQ-07 | **IF** користувач намагається оформити замовлення без жодної позиції, **THEN** система **SHALL** не створювати Order і показати повідомлення "Додайте щонайменше один товар до замовлення". |
| REQ-08 | **IF** платіжний сервіс повернув відмову, **THEN** система **SHALL** не змінювати Order і показати повідомлення "Оплата не пройшла. Спробуйте ще раз". |
| REQ-09 | **WHEN** адміністратор змінив ціну товару, система **SHALL** оновити Ingredient.Price. |
| REQ-10 | **WHEN** адміністратор змінив Ingredient.Price, система **SHALL** залишити PriceAtOrder без змін у всіх ItemQuantity, створених до цієї зміни. |
| REQ-11 | **WHEN** користувач підтвердив вибір Ingredient для підбору, система **SHALL** враховувати, чи вистачає кількості кожної Category для рецепта. |
| REQ-12 | **WHEN** користувач відкрив Recipe, система **SHALL** показати EquipmentNote цього рецепта. |
| REQ-13 | **IF** адміністратор намагається опублікувати Recipe без жодного RecipeItemQuantity або без жодного RecipeTaste, **THEN** система **SHALL** не публікувати рецепт і показати повідомлення "Рецепт має містити щонайменше одну категорію-інгредієнт і один смак". |
| REQ-14 | **IF** адміністратор намагається зберегти Ingredient без Category, **THEN** система **SHALL** не зберігати товар і показати повідомлення "Оберіть категорію для товару". |
| REQ-15 | **IF** адміністратор намагається зберегти Category без Unit, **THEN** система **SHALL** не зберігати категорію і показати повідомлення "Вкажіть одиницю виміру для категорії". |

## Нефункціональні вимоги

| ID | Вимога |
|---|---|
| NFR-01 | Система **SHALL** коректно працювати у браузерах Chrome, Opera, Microsoft Edge і Firefox (дві останні основні версії кожного) на десктопі та телефоні з шириною екрана від 360 px, так що всі вимоги REQ-01 - REQ-15 виконуються. |
| NFR-02 | Система **SHALL** відображати інтерфейс і повідомлення про помилки українською мовою. |
| NFR-03 | **IF** кількість одночасних користувачів перевищує 300, **THEN** система **SHALL** не допускати нових користувачів і показати їм повідомлення "Сервіс тимчасово перевантажений. Спробуйте за кілька хвилин", а вже підключені користувачі продовжують працювати. |
| NFR-04 | Під навантаженням NFR-03 система **SHALL** повертати видачу рецептів за фільтром смаку (UC-02) з p95 часу відгуку ≤ 500 мс. Час міряється від отримання запиту сервером до відправки відповіді. Профіль запитів: 300 одночасних користувачів, кожен запускає фільтр за смаком раз на 10 секунд. Вимірювання триває 15 хвилин, перші 2 хвилини не враховуються. |
| NFR-05 | Система **SHALL** не зберігати дані банківської картки (номер, термін дії, CVV) і платіжний токен. |
| NFR-06 | Система **SHALL** приймати результат оплати (успішно чи відмова) лише від зовнішнього платіжного сервісу й не виконувати списання самостійно. |
